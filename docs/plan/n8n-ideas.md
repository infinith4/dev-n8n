# n8n 活用アイディア集

## Context
dev-n8nリポジトリはn8n + PostgreSQLのローカル開発環境が構築済み。この環境を活用して実現できるワークフロー自動化のアイディアをまとめる。

---

## 1. 開発・DevOps 自動化

- **GitHub Issue → Slack通知**: 新しいIssueやPRが作成されたらSlack/Teamsに自動通知
- **CI/CDパイプライン補助**: デプロイ完了時にSlack通知、失敗時に自動でIssue作成
- **定期的なセキュリティスキャン**: 依存パッケージの脆弱性を定期チェックし、結果をメール送信
- **コードレビューリマインダー**: レビュー待ちPRが一定時間経過したら担当者にリマインド
- **リリースノート自動生成**: マージされたPRからリリースノートを自動生成

## 2. データ収集・監視

- **Webスクレイピング**: 定期的にWebサイトから情報収集し、スプレッドシートやDBに保存
- **API定期ポーリング**: 外部APIから定期的にデータを取得して蓄積
- **サーバー死活監視**: エンドポイントを定期的にヘルスチェックし、異常時にアラート
- **RSS/ニュース収集**: 技術ブログやニュースサイトのRSSを収集してSlackに投稿
- **株価・為替レート監視**: 閾値を超えたら通知

## 3. AI/LLM連携

- **ChatGPT/Claude API連携ボット**: Slackメッセージを受け取り、LLMで回答を生成して返信
- **ドキュメント自動要約**: 新しいドキュメントが追加されたら自動で要約を生成
- **メール自動分類・返信下書き**: 受信メールをAIで分類し、返信の下書きを生成
- **画像解析ワークフロー**: アップロードされた画像をVision APIで解析、結果をDBに保存
- **議事録自動生成**: 音声ファイルをWhisper APIで文字起こし → LLMで議事録に整形

## 4. 業務プロセス自動化

- **承認ワークフロー**: フォーム送信 → 上長にメール → 承認/却下 → 結果通知
- **請求書処理**: 請求書メール受信 → PDF解析 → 会計システムに登録
- **顧客オンボーディング**: 新規顧客登録 → ウェルカムメール → CRMに登録 → タスク作成
- **定期レポート生成**: DBからデータ取得 → グラフ生成 → PDF作成 → メール送信
- **勤怠管理連携**: Slackコマンドで出退勤打刻 → スプレッドシートに記録

## 5. マーケティング・SNS自動化

- **SNS一括投稿**: 1つのコンテンツをTwitter/LinkedIn/Facebookに同時投稿
- **フォロワー分析**: SNS APIからフォロワーデータを取得し、定期的に分析レポート作成
- **メルマガ自動配信**: 新しいブログ記事公開 → メルマガ作成 → 配信リストに送信
- **口コミ・レビュー監視**: Google/SNSでの言及を監視し、ネガティブな投稿を即座に通知

## 6. IoT・物理デバイス連携

- **スマートホーム連携**: センサーデータ受信 → 条件に応じてデバイス制御
- **Webhook受信サーバー**: 外部サービスからのWebhookを受信して処理を実行
- **環境データ収集**: 温度・湿度センサーのデータを定期収集してダッシュボード用DBに保存

## 7. ファイル・ドキュメント管理

- **Google Drive/Dropbox同期**: 特定フォルダのファイル変更を検知して別サービスに同期
- **画像リサイズ・変換**: アップロードされた画像を自動でリサイズ・フォーマット変換
- **バックアップ自動化**: DBやファイルの定期バックアップをクラウドストレージに保存
- **ファイル命名規則の強制**: アップロードされたファイルを自動でリネーム・整理

## 8. PM向け: 上流工程（要件定義〜基本設計）支援

- **要件ヒアリング受付→台帳化**: フォーム/Slack/メールで要望受付 → チケット（Jira/GitHub Issues）起票 → 要件台帳（Notion/Confluence/スプレッドシート）に追記 → 自動採番
- **要件テンプレ自動生成**: チケット作成時に「目的/背景/スコープ/非スコープ/受入条件/制約/関係者/期限」テンプレを自動挿入（空欄は入力依頼でリマインド）
- **決定事項（Decision log）自動化**: 会議メモ/議事録の入力 → LLMで「決定/未決/論点/宿題/期限/担当」抽出 → 決定ログに追記 → 関係者へ通知
- **課題・リスク台帳の自動更新**: 新規リスク検知（キーワード、未回答、期限超過） → リスク台帳更新 → 重要度に応じてエスカレーション（Slack/メール）
- **変更要求（CR）フロー**: 変更要求フォーム → 影響範囲（要件/設計/工数/スケジュール）入力依頼 → 承認フロー → 承認結果でバックログやドキュメントに反映
- **トレーサビリティ補助**: 要件ID ↔ 設計項目 ↔ チケット ↔ テストケース を紐付ける行を自動生成し、リンク切れ・未紐付けを検知して通知
- **定例レポート自動生成**: Jira/GitHub/カレンダー/台帳から進捗・滞留・ブロッカーを収集 → 週次報告を自動整形 → Slack/メール投稿（必要ならLLMで要約）

## 9. PM向け: ドキュメント整理・ガバナンス

- **ドキュメント一元インデックス**: Drive/SharePoint/Notion/Confluence の更新イベントを拾い、タイトル/URL/作成者/更新日/タグをインデックス（検索用DB/スプレッドシート）
- **命名規則・格納先の自動強制**: ファイル名パターンチェック（`PJ-領域-種別-YYYYMMDD-vX` など） → 逸脱時は自動リネーム案提示 or 差し戻し通知
- **タグ付け・要約の自動付与**: 新規/更新ドキュメント → LLMでタグ（領域、機能、顧客、優先度）付与 + 200字要約 → ページ先頭やメタ情報に追記
- **重複/競合の検知**: 類似タイトル/類似内容（要約ベース）を検知し「既存と統合候補」を提示
- **レビュー/承認リマインダー**: 「作成後X日でレビュー」「更新後Y日で再承認」などのルールをCronで走らせ、期限前後に自動通知
- **陳腐化（stale）検知**: 最終更新が一定期間超の重要ドキュメントを抽出し、オーナーへ棚卸し依頼（更新/廃止/後継リンク付与）
- **議事録→タスク分解→登録**: 議事録テキスト → 宿題リスト化 → チケット作成 → 期限が近い順にSlackでリマインド
- **Google SpreadsheetのWBS → NotionタスクDB同期**: WBSをスプレッドシートで作成/更新 → n8nで行を取得 → Notion Databaseに「Upsert（新規作成/更新）」してタスク化（`wbs_id` などの一意キーで突合）。列マッピング例: `担当/状態/開始/終了/見積/実績/優先度/親タスクID/マイルストーン/URL`。親子は `親ID` を見てRelationで紐付け、階層や集計（担当別/週次）をNotion側でビュー化。
- **差分検知・双方向更新**: 変更検知用に `updated_at` / `hash` を持たせ、差分だけ反映。Notion側で更新された担当/ステータスを逆流（Notion→Sheets）させる場合は「どちらを正とするか（片方向 or フィールド単位の優先）」をルール化して衝突を回避。
- **中間データ（JSON/CSV）での連携基盤**: Sheets→JSON/CSVに正規化してPostgreSQLに格納（履歴テーブルも用意）→ Notion/Jira/GitHub Projects など複数ツールへ配信。WBSのスナップショット（週次）を残して差分レポートも自動生成。
  - 要件定義: `docs/plan/wbs-sync-requirements.md`

## 10. カスタマーサポート

- **チケット自動振り分け**: 問い合わせ内容をAIで分析し、適切な担当者に振り分け
- **FAQ自動応答**: よくある質問パターンを検知し、自動で回答を返信
- **SLA監視**: 対応期限が近づいたチケットをエスカレーション通知
- **顧客満足度調査**: サポート完了後に自動でアンケートを送信・集計

## 11. Eコマース・決済

- **在庫アラート**: 在庫が閾値を下回ったらSlack通知 + 自動発注メール
- **注文処理自動化**: 注文受信 → 在庫確認 → 出荷指示 → 顧客に追跡番号通知
- **Stripe/PayPal連携**: 決済完了Webhook → 顧客にサンクスメール → 売上記録

## 12. 社内ツール連携

- **Notion ↔ Slack連携**: Notionのページ更新をSlackに通知
- **Googleカレンダー連携**: 予定の15分前にSlackリマインド + 会議URLを自動取得
- **Jira ↔ GitHub同期**: Jiraチケットの状態変更をGitHub Issueに反映、またはその逆
- **スプレッドシート ↔ DB同期**: Googleスプレッドシートの変更をPostgreSQLに自動反映

---

## 実装時の補足

- 本リポジトリの `src/docker-compose.yml` で n8n + PostgreSQL 環境が起動可能
- n8nはポート `5678` でアクセス（http://localhost:5678/）
- Webhookトリガーを使えば外部サービスからのイベント駆動型ワークフローが構築可能
- Credentialは n8n のUI上で安全に管理可能
